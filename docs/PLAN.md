## 1. The refined prompts

### 1.1 Product brief (condensed)

> Build Berth, an open-source desktop app in Rust (Dioxus 0.7, system webview) for developers who run Docker through Colima on an Apple Silicon Mac. A container is known by the folder it came from: every list starts from projects (folders found through Compose labels or pinned by the user), and a folder with no Docker setup gets one generated by rules and shown as a diff before anything is written. Berth manages every Colima profile (start, stop, resize), shows dense tables of containers, images, volumes and networks with visible Start, Stop, Restart, Pause, Kill and Delete buttons, streams and searches logs across containers, opens a terminal in any container, finds images on Docker Hub, frees disk space with the total shown first, and detects 15 known Docker errors with a plain explanation and a fix. It takes Portainer's developer features (edit and recreate, live limits, templates, registries, deploy from Git, activity log, remote engines) and leaves out the operations-fleet ones. An installed AI harness (Claude Code or muse) can be driven as an interactive assistant that reaches Docker only through Berth's MCP tools: reads run at once, changes need a click, destructive actions need the name typed, and file edits always land on the Review changes screen. Coolify is the first plugin, out of process. A menu bar item shows engines, projects and failing containers. Dense UI (13px text, 28px rows), keyboard first, and a hard performance budget (cold start under 600 ms, 10k log lines per second, idle CPU under 0.5 %). No accounts, no telemetry.

### 1.2 Execution brief

> Write the plan so a less capable model (Sonnet, the workhorse) can build the whole product one task per session without making architectural decisions. Opus is the architect and reviewer. The plan resolves every open decision in one register, fixes the dependency list against the registry, writes the Rust interfaces every crate implements, specifies the UI against the FigCraft frames, lists the commands each session runs to prove its work, breaks every phase into one-session tasks with a mechanical done-when check, and says when the workhorse must stop and escalate.
>
> Build host: **this Mac only** (macOS 27, Apple Silicon). Every check runs here: cargo checks, unit, SSR and integration tests against Colima on this Mac, and for UI tasks the running app captured with `scripts/shot.sh` and compared with its FigCraft frame. macOS features (menu bar item, Keychain, native open panel and folder privacy prompts, Open in Terminal app, harness detection from a Finder-launched app, Colima vz and Rosetta, Cmd shortcuts, the macOS menu) are normal tasks in the phase where they belong; packaging, signing, notarization, release and the clean-install test are the last phase.

## 3. Operating model: Opus architects, Sonnet builds

| Role | Model | Does | Does not |
|---|---|---|---|
| Architect | Opus | Owns this plan, `TASKS.md` and the ADRs. Opens each phase (re-reads its tasks, writes the "Learned" paragraph from STATUS.md, adjusts tasks only where STATUS.md proves an assumption wrong). Closes each phase with the review gate below. Answers every entry in `docs/QUESTIONS.md`. Signs off each UI task's shots at phase close. | Write feature code during a workhorse task. |
| Workhorse | Sonnet | One task from `TASKS.md` per session, in order. Implements the interfaces in §6 exactly. Runs `scripts/check.sh` and the task's check. Updates `docs/STATUS.md`. Commits. | Change an interface, add a dependency, skip a check, or decide an open question. Those are escalations. |

**Escalation rule.** The workhorse stops the task, appends an entry to `docs/QUESTIONS.md` (task id, what blocked it, the two options it sees, which it would pick), notes it in STATUS.md, commits and ends the session when any of these is true:

1. The task needs a change to a type or trait in §6, or a new public type shared across crates.
2. The task needs a crate not in §5, or a different major version.
3. The done-when check still fails after two honest, different attempts.
4. A rule in `CLAUDE.md` would have to be broken.
5. The task text contradicts the code that exists.

Everything else the workhorse decides and records in STATUS.md under "Decisions made". A helper's name, a fixture's shape or a padding value never escalates.

**Review gate the architect runs at each phase close.**

1. `scripts/check.sh` exits 0 on the phase branch.
2. The phase's acceptance check in §9 passes, run by hand on this Mac, not read from STATUS.md.
3. `git diff main...HEAD -- crates/berth-core crates/berth-plugin-protocol` shows no interface change without an ADR or a §6 edit.
4. `scripts/secret-scan.sh` finds no fixture password, token or `.env` value outside `fixtures/` and `scripts/`.
5. Each new test fails when the behaviour it covers breaks (spot-check two by reverting a line).
6. `docs/QUESTIONS.md` has no open entries that block the next phase.
7. Merge to `main`, tag `v0.N` locally, bump the workspace version, write the next phase's "Learned" paragraph.

**Session size.** One task per workhorse session. If a task finishes in under a third of a session, the workhorse may start the next task only when it is in the same phase and touches the same crate. Architect sessions are one phase open or one phase close.

### 4.2 Runtime and code conventions

| # | Decision | Choice |
|---|---|---|
| D11 | Async runtime | Tokio multi-thread through dioxus-desktop's `tokio_runtime` feature (default on). Background work uses `tokio::spawn`. Anything that can take over 4 ms off the UI path uses `spawn_blocking` (brief §1.3 rule). |
| D12 | Async traits | `async_trait` on every trait used as `dyn`. |
| D13 | Cancellation | `tokio_util::sync::CancellationToken` passed into every stream (events, logs, stats, exec, pull, build), every subprocess (compose, colima, git, harness, plugin) and every bridge call. Subprocesses use `kill_on_drop(true)`. |
| D14 | Errors | `thiserror` enums, one per library crate: `CoreError`, `SysError`, `StoreError`, `SecretError`, `EngineError`, `LogsError`, `RulesError`, `RegistryError`, `AssistantError`, `PluginError`. `anyhow` only in `berth-app/src/main.rs` and plugin binaries' `main.rs`. Every error's `Display` is a user-facing sentence. |
| D15 | Logging | `tracing` + `tracing-subscriber` (`env-filter`, `json`) + `tracing-appender`. File sink `~/Library/Logs/Berth/berth.log`, daily rotation, 7 files; stderr in debug builds. `BERTH_LOG=debug` raises the level. `bollard`, `hyper`, `reqwest` and `rmcp` stay at `warn` always (Ferry: bollard debug logs carry container environments). Never log env values, `.env` values, secrets, tokens or prompt text. |
| D16 | IDs | Newtypes, never bare strings (brief §5). `EngineId` is `"colima:<profile>"`, `"context:<name>"`, `"ssh:<host>"`, `"tcp:<host:port>"`, `"socket:<path>"`. `ProjectId` is the first 16 hex chars of SHA-256 over `canonical_folder + "\0" + engine_id` (`RemoteOnly`: compose project name instead of folder). `ContainerId` holds the full id. `ProblemId` is SHA-256 of `kind + subject` (16 hex). `uuid` v7 for activity rows, assistant sessions, approvals and plugin request ids. |
| D17 | Time | `chrono`, UTC, RFC 3339 text in SQLite. Uptime and ages formatted by one pure `berth_core::fmt` module. |
| D18 | Serialization | `serde` + `serde_json` everywhere. YAML read with `serde_norway` 0.9 (the maintained `serde_yaml` fork; `serde_yaml` is deprecated and `serde_yml` unmaintained on crates.io 2026-10-24). TOML read with `toml` 1. |
| D19 | Local store | `rusqlite` 0.41 (`bundled`) at `<data dir>/berth.db`. Numbered migrations embedded with `include_str!`, table `schema_version`. Tables in §6.4. |
| D20 | Secrets | `keyring` **3.6** with the `apple-native` feature (not 4.x: 4.2 replaced the backend model; 3.x is proven by Ferry with a Developer-ID-signed app on this Mac). Service `dev.berth`. Keys: `registry/<registry_id>/password`, `plugin/<plugin_id>/<key>`, `engine/<engine_id>/tls-key-passphrase`. `InMemorySecretStore` for tests; `BERTH_KEYRING=memory` forces it. ADR 0007. |
| D21 | Paths | `directories` 6, `ProjectDirs::from("dev", "berth", "Berth")`. `BERTH_DATA_DIR=<dir>` puts `berth.db`, logs, bridge sockets and session files under `<dir>`. |
| D22 | State | Dioxus signals. One `AppState` struct provided through context (`crates/berth-app/src/state.rs`). No router: a `Section` enum plus overlay stack. No global statics. |
| D23 | Data flow | The UI never calls an engine. Services in `crates/berth-app/src/services/` own every I/O task and write signals. Lists update from `docker events`; a full refresh happens only on (re)connect. Cold start renders the last snapshot from SQLite, then live data replaces it (brief §1.3). |
| D24 | Virtual lists | Every list that can exceed 100 rows is virtual: fixed row height (28 px, 24 compact), 10-row overscan, pure `visible_range(scroll_top, viewport_h, row_h, total, overscan) -> Range<usize>` (Ferry D23 pattern). Rows are plain elements, no per-row effects. |
| D25 | Logs pipeline | `berth-logs` keeps a ring buffer of 100,000 lines per view, classifies level and error marks in Rust, searches in Rust (plain or regex), and flushes to the UI at most once per 16 ms tick. | D26 | Stats | One `stats` stream per visible container row or open Stats tab, closed on scroll-out and when the window is hidden. Missing stats show "—", never 0. | D27 | Compose | The `docker compose` CLI (v2 plugin) as a subprocess: `docker compose --project-directory <folder> -f <file>… -p <name> --progress json <cmd>` with `DOCKER_HOST` set to the engine's endpoint. Bollard is never used for Compose. ADR 0003. |
| D28 | Colima | The `colima` CLI as a subprocess. List with `colima list --json` (one JSON object per line), status with `colima status -p <profile> --json` (field `docker_socket`), `start`/`stop`/`restart -p <profile>`; resource edits are `colima stop` then `colima start -p <p> --cpus N --memory GiB --disk GiB [--vm-type vz] [--vz-rosetta]`. ### 7.5 Bridge messages (sealed web bundles, ADR 0004)

Rust to JS through `document::eval`; JS to Rust through `dioxus.send(JSON.stringify(msg))` on the same eval handle (Ferry ADR 0005 pattern). Rust deserializes into typed enums and ignores unknown types.

| Direction | Message |
|---|---|
| Rust → JS | `berth.term.create(id, {fontSize, theme, scrollback: 5000})`, `berth.term.write(id, base64)`, `berth.term.clear(id)`, `berth.term.focus(id)`, `berth.term.copySelection(id)`, `berth.term.setTheme(theme)`, `berth.term.dispose(id)` |
| JS → Rust | `{"type":"term.ready","id"}`, `{"type":"term.input","id","data":base64}`, `{"type":"term.resize","id","cols","rows"}`, `{"type":"term.title","id","title"}` |
| Rust → JS | `berth.editor.create(id, {lang:"yaml"|"dockerfile"|"text", value, readOnly, theme})`, `berth.editor.setValue(id, text)`, `berth.editor.getValue(id)` (answers with `editor.value`), `berth.editor.setMarks(id, [{line, message}])`, `berth.editor.setTheme(theme)`, `berth.editor.dispose(id)` |
| JS → Rust | `{"type":"editor.ready","id"}`, `{"type":"editor.change","id","text"}` (debounced 150 ms), `{"type":"editor.value","id","text"}`, `{"type":"editor.save","id"}` |
| Rust → JS | `berth.ui.scrollTo(elementId, top)`, `berth.ui.copy(text)` (clipboard, D60) |

### 7.6 Logs view rules

Rows are 18 px (12/18 mono). Columns: gutter mark (error red bar, warn amber), timestamp (muted, toggle), container name in `series-N` colour (merged views only), message. Error and warn lines get the whole-row tint (`log-error-bg`, `log-warn-bg`). JSON lines show `level · message · k=v …` with a chevron to expand a tree. Folded stack traces show "N more lines". Search highlights matches and shows "3 of 41"; an invalid regex shows the error inline under the field. With Follow off, new lines do not scroll the view and a pill "142 new lines" appears; clicking it turns Follow on. Selecting lines (click, shift-click) shows a floating bar "Explain · Ask about these lines" (Ask needs a harness; Explain runs the rules first). The ring buffer drop shows "Older lines dropped; Save to keep all" at the top.

### 7.7 Tokens

`scripts/gen-tokens.py design/tokens.json > crates/berth-app/assets/css/tokens.css` writes:

- `:root` light values: `--color-<role>` for every role in `color` (bg, surface, surface-raised, surface-sunken, surface-hover, surface-pressed, selection, ink, ink-muted, ink-disabled, line, line-strong, accent…, success…, warning…, danger…, info…, stopped…, *-dot, log-*, tooltip*, focus, series-1…5); ramps as `--<ramp>-<step>`.
- dark values from `dark.color` under both `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { … } }` and `:root[data-theme="dark"] { … }` (D7).
- `--font-text`, `--font-mono`, `--text-<role>-size`, `--text-<role>-line`, `--text-<role>-weight`, `--space-<n>`, `--radius-<sm|md|lg|full>`, `--size-control-<sm|md|lg>`, `--size-row`, `--size-icon-<sm|md>`, `--size-sidebar`, `--size-inspector`, `--size-titlebar`, `--shadow-<popover|sheet|dialog>`, `--motion-<name>`, `--ease-standard`.
- `:root[data-density="compact"] { --size-row: 24px; }` (density never changes text size).
- `@media (prefers-reduced-motion: reduce)` sets every `--motion-*` to 0 ms except progress.

Components use only these variables. No hex colour appears in any component CSS (`scripts/check.sh` greps for it).

## 10. Session protocol

The repository is the memory. A fresh session with no context continues from the files alone.

**Start of every session:** read `CLAUDE.md`, `docs/STATUS.md`, the current phase header and its "Learned" paragraph in `docs/TASKS.md`, the task, and the PLAN sections it cites. Run `scripts/check.sh` before changing anything; it must be green.

**End of every session:** `scripts/check.sh` exits 0; run the task's done-when (for UI tasks, `scripts/shot.sh` and read the shot beside the frame PNG); paste the output into STATUS.md; update STATUS.md (what works, what is half done, next task id, decisions made, versions pinned); commit `P<N>-T<M>: <what>`.

**Reset after drift.** If a session loses the thread: discard uncommitted work, re-read STATUS.md, redo the task. If a phase drifted beyond repair: `git checkout v0.(N-1)`, new branch, start the phase again. The plan and ADRs never change on a reset; only code does.

**Parallel worktrees.** §9.2. Each worktree has its own `BERTH_DATA_DIR` and runs `scripts/it.sh` one at a time against the engine (the fixtures are shared).

**Commands that change the owner's machine.** Starting, stopping or resizing a Colima profile, and anything outside the berthfx fixtures, run only when the task says so and the owner is present (CLAUDE.md).

## 13. Risks

| Risk | Mitigation |
|---|---|
| Dioxus 0.7 API differs from this plan | P0 pins 0.7.10; real API names go to STATUS.md; the workhorse adapts names, never structure; structural gaps escalate. Ferry's lessons are D5, D7, D8, D39, D59, D60. |
| WKWebView too slow for 1,000-row tables and 10k lines/s | Virtual lists (D24), Rust-side log buffer and per-frame batching (D25), only visible stats (D26); measured by the P3 throughput test and the P6 acceptance check. Escape hatch: reduce overscan, batch at 33 ms. |
| A UI task drifts from its frame | Every UI task reads the frame PNG first, adds its scene and SSR tests that assert copy and states, and ends with a shot read beside the frame; P10 re-audits every scene. |
| Harness flags or MSP shape change | Flags are constants in one table per adapter; smoke tests run the real CLIs when `BERTH_HARNESS_SMOKE=1`; versions verified 2026-10-24 (Claude Code 2.1.309, Muse Code 1.4.12, MSP schema fingerprint `sha256:cfdb6d25…b4e0`). `--allowedTools mcp__berth` and muse's handling of MCP tool approvals are unverified until P7-T3/T4. |
| A harness runs a destructive Docker action | Harnesses get no built-in tools (`--tools ""`, muse `--disable-shell --disable-write`) and reach Docker only through Berth's tools, which are gated in the app (D44). |
| `.env` values or tokens leak to a harness, plugin or log | Redaction in `berth-assistant::redact` (tested), tracing levels pinned (D15), `scripts/secret-scan.sh` in `check.sh`. |
| `exec format error` fix depends on Rosetta | The fix offers "Restart Colima with Rosetta" only for vz profiles; otherwise it offers `platform: linux/arm64` or an arm64 tag. |
| Silent writes into the user's repo | D31: one write path, conflict check, folder bound; Review changes is the only caller. |
| Integration tests damage the owner's own containers | Fixtures are labelled and prefixed; prune and remove in tests take explicit item lists; CLAUDE.md forbids touching unlabelled resources. |
| Plugin with a Coolify token deploys to production by mistake | Every Coolify action confirms with app name, server and branch; permissions shown at enable; token only through `host/secret.get`. |
| Tests touch Colima itself (stop, resize) and interrupt the owner's other work | Only P4-T6 and the P4 acceptance change a profile, and only with the owner present; ITs use the berthfx fixtures. |
| Keyring 3.x falls behind | It is proven on this Mac; moving to 4.x is an ADR with a migration task. |
| Scope creep | §2 is the contract. New ideas go to "Later". |
