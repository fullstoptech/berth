# Berth design system

Date: 2026-10-24 · Archetype: **dense-pro** (bands key `dense-pro`) · Source of truth: `design/tokens.json`, generated by `design/build_tokens.py`.

The one visual idea: **status is the only colour on the screen.** Neutral grey chrome, one blue accent for action and selection, and green, amber and red reserved for the state of containers and engines. Someone glancing at the window from across the room should be able to tell whether anything is broken.

## Decisions

| Axis | Decision | Reason tied to Berth |
|---|---|---|
| Colour strategy | Near-pure grey neutrals (OKLCH chroma 0.006 at the accent hue). One accent: signal blue, hue 252. Status hues: green 150 (running, healthy), amber 72 (restarting, unhealthy, paused, amd64 under emulation), red 27 (exited with error, failed, destructive). Stopped is **neutral grey**, not a colour. | Every row in every table carries a status; if chrome carried colour too, a failing container would not stand out. Stopped is grey because stopping is normal, not a warning. Blue sits 100° from green and 180° from amber, so a selected row is never read as a state. Docker's own brand blue is not used. |
| Second hue | Eight categorical colours (`series-1…8`, equal lightness, spaced hues) used **only** for container names in merged logs. | Merged logs from five containers must be told apart at a glance; this is the only place a categorical palette has a job. They never mean status. |
| Type | **IBM Plex Sans** for UI text; **JetBrains Mono** for IDs, ports, image tags, paths, logs and terminal. Body 13/20. Roles: caption 11, label 12/500, body 13, h3 13/600, body-lg 15, h2 15/600, h1 18/600, display 24/600, code 12/18. | See the typeface comparison below. 13px body is inside the dense-pro band (13 to 16) and matches macOS's own 13pt UI default; 12px mono for logs reads because JetBrains Mono's x-height is 0.55 of the em. |
| Numerals | Tabular figures everywhere numbers sit in columns: CPU %, memory, sizes, uptime, ports, timestamps. | Both families have tabular figures by default, so columns line up without a feature flag. |
| Space | 4px base: 0, 2, 4, 6, 8, 12, 16, 20, 24, 32, 40, 48. The 2 and 6 steps have a job: icon-to-label gaps and badge padding inside 24 to 28px rows. Inside components 4 to 8; between groups 12 to 24; between page sections 32. Page gutter (`layout.gutter`): 16px, 20px from a 1200px-wide window up; buttons side by side in a row or the bulk bar sit 8px apart. | Rows are 32px; anything coarser than 4 cannot place an icon, a status dot and a label inside one row. Berth is scanned row by row; 32 px is the dense-pro compact floor (Carbon/Cloudscape/Primer/SLDS/Geist bands). Owner, 2026-10-25: "the general spacing seems tight" (decision D11). |
| Density | Comfortable 32px rows by default; app-wide **Compact** (24px rows, 24px controls; targets never shrink) in Settings. Text sizes never change with density. Dialogs, banners and the Review changes sheet are exempt. | One expert user, all day on a laptop screen: compact is a real preference, but shrinking 13px text further would cost log legibility (Carbon's side over SLDS). |
| Shape | Radius sm 3 (badges, checkboxes, row buttons), md 5 (buttons, inputs, menus), lg 8 (sheets, palette, popovers), xl 12 (dialogs). Nested radius = outer minus padding. | Small radii match a desktop tool and keep 24px buttons from looking like pills. |
| Elevation | Resting surfaces are flat and separated by 1px lines. Shadow only for floating layers: popover (menus, tooltips), sheet (palette, Review changes), dialog. In dark mode depth comes from lighter surfaces (`surface-raised` is two steps lighter) plus the same shadows. | A desk of panels, not a stack of cards: shadows mean "above the work". |
| Motion | instant 0, micro 100 (hover, press), short 150 (tooltip, popover, row expand), enter 200 (sheets, palette), exit 140; toast dwell 5 s, 10 s with an action. Easing standard `cubic-bezier(0.2,0,0,1)`. Reduced motion: everything becomes instant except progress indicators. | Dense-pro keeps every move under 200ms; nothing sits between the user and the next action. |
| Control sizes | Controls sm 24, md 28, lg 32; table rows 32 (compact 24); sidebar and menu rows stay 28; icon 14 and 16. Minimum target 24px (WCAG 2.2 target size, pointer input). | A pointer-only desktop app: 44pt touch targets would double row height. 24px meets WCAG 2.2 AA (2.5.8) and fits inside a 32px row. Berth is scanned row by row; 32 px is the dense-pro compact floor (Carbon/Cloudscape/Primer/SLDS/Geist bands). |
| Proof elements | Status as dot + label, never colour alone; every destructive or file-writing action states its full effect and repeats counts and sizes on the button and the result; the Activity log as the audit trail; row action buttons always visible on the selected row. | The brief's trust job: data is never hidden, stale or ambiguous, and nothing changes without saying what changes. |

## Typeface, chosen by comparison

Strings the product shows: `0.0.0.0:5432→5432/tcp`, `postgres:17-alpine`, `a3f9c2e1b7d4`, `14.2 GB`, `api-worker-7f9c4d8b6-xk2lp`, `exec format error`, `Remove 41 items (14.2 GB)`, arrows, middle dots, ellipses and dashes.

| Candidate | Check (fonts.py, 2026-10-24) | Verdict |
|---|---|---|
| **IBM Plex Sans** (OFL-1.1) | Pass: → · … — – × present; tabular figures by default; 7 weights; x-height 0.516 | **Chosen for UI text.** Engineering voice without being a reflex choice; open licence so it ships inside the app; renders the same on macOS and Linux (Linux is the second platform); tabular by default for every table. |
| Schibsted Grotesk (OFL-1.1) | Pass; tabular only through the `tnum` feature | Narrower and more editorial; needs `tnum` switched on everywhere a number appears, an easy thing to forget in a table-heavy app. |
| Hanken Grotesk (OFL-1.1) | Fail on ↑ ↓ ✓ | Removed. |
| SF Pro (platform face) | Not checkable through Google Fonts; has every glyph, including ⌘ | Most native on macOS and costs no bytes, but Apple's licence limits it to Apple platforms, so Linux would get a different face and different column widths. Kept as the fallback in the font stack. |
| **JetBrains Mono** (OFL-1.1) | Pass; x-height 0.550 | **Chosen for mono.** Tallest x-height of the candidates, so 12px logs stay readable; distinct 0/O and 1/l/I matter in container IDs. Ligatures are switched off in logs. |
| IBM Plex Mono (OFL-1.1) | Pass; x-height 0.516 | Would match the sans, but reads smaller at 12px in a log wall. |

Keyboard symbols ⌘ ⌫ ⇧ ⌃ ✓ are missing from every Google family; they are drawn from the icon set in the `Kbd` component, not typed as text.

## Ramp jobs

- `neutral` (light): 0 surface, 50 sunken, 100 window ground and hover, 200 lines and pressed, 400 disabled ink, 500 strong lines and stopped dots, 700 muted ink, 900 ink.
- `neutral-dark`: 50 window ground and sunken, 100 surface, 200 raised, 300 lines and pressed, 500 disabled ink, 600 strong lines and stopped dots, 700 muted ink, 900 ink.
- `blue`: 50 info background, 100 selection, 600 focus, 700 accent and info text, 800/900 hover and pressed; dark uses 300 for accent and focus, 950 for selection.
- `green`, `amber`, `red`: 50 subtle background, 600 or 700 text and dots, 300 in dark, 950 dark subtle background.

## Round 1 changes (art-director, 2026-10-24)

The critic found the light theme on-idea but the dark theme off it: every status hue and the accent sat at the same pastel lightness (L 0.86), so in dark "status pops" became "pastel theme", and Running vs Exited (137) were nearly identical for deuteranopes. Applied:

1. **Separate dot roles** (`success-dot`, `warning-dot`, `danger-dot`, `info-dot`): light green.700 / amber.500 / red.600 / blue.600; dark green.400 / amber.400 / red.500 / blue.400; dark `stopped` to neutral-dark.700. Badge text keeps the old steps on `*-subtle`. Every dot is at least 3.2:1 on its surface (dark at least 5.1).
2. **Saturated fills with white labels in both themes** (`accent-fill`, `danger-fill` and their hover, pressed and `on-*` roles): the macOS dark pattern. Dark primary is blue.600 with white (4.69:1); destructive red.600 with white (5.12:1). `accent` and `danger` are now text and link roles only.
3. **Dark surface ladder lifted**: bg neutral-dark.100, surface 200, raised 300, hover 300, pressed 400, sunken stays 50; a new neutral-dark.450 step for hairlines (1.43:1 on surface, was 1.18).
4. **Series palette cut to five cool and pink hues** (252, 196, 300, 340, 225). Green, amber and olive names in merged logs read as status, which breaks the one visual idea where it matters most.
5. **Log lines carry level**: `log-error-bg`/`log-error-ink` and `log-warn-bg`/`log-warn-ink` tint the whole line (dark backgrounds are the 950 step at 40% over the surface, flattened to hex).

Smaller: `radius.xl` removed (dialogs use lg 8, inside the brief's 3 to 8); `motion.enter` 150 and `exit` 100 (brief: under 150 ms); display tracking −0.01em, h1 −0.005em. **Container names are set in IBM Plex Sans** (they are the row's title and are read, not compared); IDs, image tags, ports, paths and hashes are in JetBrains Mono.

Checks after the round: `tokens_check.py` 0 failures; `ds_score.py` 4 pass, 0 fail, 2 warn (unchanged advisories).

## Round 2 changes (art-director on components, 2026-10-24)

- **Red only where something is wrong.** Row Delete buttons stay visible (Emmanuel's requirement) but rest in muted ink and turn red on hover; Kill and Delete in the inspector are secondary buttons with a red icon; `danger-fill` is used only by the button that commits a destructive confirm. The title bar's problem count is the red mark instead.
- **Dark subtle backgrounds are flattened tints** (950 at 40% over the surface) for every status, so diffs, failed fixes and error rows are tints with a 2px bar in the dot colour, never slabs.
- **macOS chrome over web-kit controls**: toggle icon buttons instead of switches in the log toolbar, a segmented control for log levels, plain-text shortcuts in menus, 24px menu rows, system traffic-light colours (a literal exception: system chrome, not status), a dark tooltip on the raised surface.
- **Controls**: sm 24, md 28 (the 24px target floor holds in compact too). Filled Start and Stop glyphs; a three-line Logs glyph; icons optically sized.
- **Rows**: one baseline per row, micro bars inline left of the value, "—" for empty cells, a real ellipsis everywhere, loading swaps only the pressed icon.
